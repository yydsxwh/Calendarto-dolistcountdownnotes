# 颗秒日事 · 旧功能与新架构映射表

> **这份文档存在的唯一目的：防止以后有人误以为这些功能可以删掉。**
>
> 读法：左边是**用户看到的东西**，右边是**代码底下怎么实现**。
> 右边可以换，左边不能消失。
>
> 配套阅读：[`existing-features.md`](existing-features.md)（现状清单 + 回归基线）。
>
> 最后更新：2026-09-19。

---

## 核心原则

```
        用户入口                  底层实现
   ┌──────────────┐        ┌────────────────────┐
   │   永远保留    │  ───▶  │  可以逐步统一、替换  │
   └──────────────┘        └────────────────────┘
```

- **合并架构 ≠ 合并产品入口。** 课表和日历共用一套时间引擎，不代表课表页面可以取消。
- **看起来重复 ≠ 可以删。** 便签和笔记、倒数日和日历事件、今日提醒和待办，
  它们的使用场景、操作速度和信息密度都不同。
- **不要造第二套。** 正确做法是「旧入口 + 新底层」，不是「旧系统 + 新系统长期并行」。

### 课表

| | |
| --- | --- |
| **用户入口** | 「课表」标签，`#schedule`。**永远保留独立页面** |
| **当前实现** | `Course` + `Term` + `parseWeekNumbers` + `buildTimeAxis` + `layoutDayCourses` |
| **未来底层** | `CourseSchedule` + `AcademicTerm` + 按需投射到 Calendar |
| **状态** | `STABLE`，增强 `PLANNED` |

**课表不是普通日历事件，绝不能被 CalendarEvent 吞掉。** 它有自己的业务语义：
课程名 / 教师 / 教室 / 星期 / 节次 / 单双周 / 教学周 / 学期 / 备注，
以及一整套导入识别（xlsx / csv / 照片 / PDF / Word）。

计划增强（不破坏现有结构）：

- `Term` 扩展教学周起止，与 `parseWeekNumbers` 打通
- 课程可投射到日历视图，**按需展开，不生成无限重复记录**
- 上课提醒接入统一 Reminder Engine

**投射方向是单向的：课表 → 日历。** 日历上看得到课，不代表课表页面可以取消。

### 提醒引擎

| | |
| --- | --- |
| **用户入口** | 各功能的「提前 N 分钟」设置 + 页内横幅 + 系统通知。**保留** |
| **当前实现** | `setInterval` 30 秒轮询 + Notification API / Capacitor Local Notifications |
| **未来底层** | `ReminderRule` + `ReminderOccurrence`（持久化） |
| **状态** | `STABLE`，重构 `PLANNED` |

**必须解决的局限**：网页端只在页面打开时轮询，触发窗口只有 90 秒，错过不补发。
这两点在回归测试里已经钉住，重构时会看到它们失败——那是**预期的**，
届时需要连同测试一起更新，并说明新的行为契约。

新设计要求：

- `ReminderOccurrence` 记录 `scheduledAt` / `deliveredAt` / `status` / `attempts`
- 用于防重复、重试、多端协调
- 禁止只依赖 `setTimeout`
- Quiet Hours（如 23:00–08:00），不做不可关闭的无限通知

### 本地存储 → 服务端权威

| | |
| --- | --- |
| **用户入口** | 无（对用户不可见） |
| **当前实现** | `localStorage['kemiao-days-v1']` 为唯一真相；登录后整份文档镜像到服务端 |
| **未来底层** | Server Source of Truth + 本地缓存 + Sync Engine |
| **状态** | `IN-PROGRESS`（PR #13） |

**迁移铁律**：

1. 线上所有真实用户数据**只**存在于各自设备的 `localStorage`，**没有服务端备份**
2. 迁移顺序：解析 → 当前登录用户确认 → 上传 → 校验 → **本地副本保留**
3. **确认云端完整之前，绝不清理本地数据**
4. 现有的冲突处理（版本号 + 询问用户）不能退化成静默覆盖

## 反向检查清单

改动前逐条自问，任何一条答「是」就停下：

- [ ] 我是不是删掉了某个标签页？
- [ ] 我是不是让某个 `#hash` 路由失效了？
- [ ] 我是不是改了 `kemiao-days-v1` 的键名或结构，导致老数据读不出来？
- [ ] 我是不是因为「日历也能显示」就取消了课表 / 倒数日的独立入口？
- [ ] 我是不是因为「有笔记了」就删了便签？
- [ ] 我是不是新造了一套周期系统，而没有先看 `calendar-core.ts` 和 `calendarEvents`？
- [ ] 我是不是让某个旧功能的回归测试失败了，却直接改测试而没说明原因？
- [ ] 我是不是在没有备份方案的情况下清理了本地数据？
